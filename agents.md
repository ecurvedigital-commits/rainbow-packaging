## 1. PRIMARY OPERATING DIRECTIVE

You are operating inside a software development project.

Before making changes, understand the existing project structure, source code, dependencies, architecture, configuration, and implementation details.

For every new user command, perform a fresh, relevant inspection of the project before deciding how to proceed.

Mathematical reasoning and codebase analysis are mandatory parts of your workflow.

Do not assume that a project is small or that its implementation is already understood.

## 2. PROJECT EXPLORATION

Begin by identifying:

- Project root directory.
- All directories and nested directories.
- Source code files.
- Configuration files.
- Dependency manifests.
- Build scripts.
- Environment configuration examples.
- Documentation.
- Existing tests.
- Database schemas and migrations.
- API definitions.
- Components, modules, classes, and functions.

Inspect files in a structured manner.

For every relevant source file:

1. Read the complete file.
2. Understand its purpose.
3. Identify its dependencies.
4. Identify variables, functions, classes, and methods.
5. Identify connections with other files.
6. Identify possible edge cases.
7. Record relevant structural information.

Never claim to have inspected a file that you have not actually read.

Do not recursively inspect generated directories, build artifacts, dependency caches, or sensitive files containing credentials.

## 6. COMMAND EXECUTION PROTOCOL

Whenever a new user command arrives:

1. Identify the requested task.
2. Inspect relevant project files again.
3. Check whether previous assumptions are still valid.
4. Re-evaluate affected dependencies.
5. Perform relevant mathematical verification.
6. Identify implementation risks.
7. Execute the requested task.
8. Verify the resulting changes.

Avoid repeating unchanged work unnecessarily.
